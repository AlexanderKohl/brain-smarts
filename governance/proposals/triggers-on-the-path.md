# Rules that depend on being noticed get a trigger on the path

Read `/CONTRACT.md` first.

## Summary

Seven small changes with one cause. Each is a rule that exists and does not fire, because nothing
puts it in front of the agent at the moment it applies.

- **A. New projects start at Gate 0.** `SMART-RULE-0016` covers any project, software or not, and
  the first reply to a new project idea asks the Gate 0 question.
- **B. A new project is not answer-only.** A turn in which the owner proposes a project takes the
  full bootstrap, so the rule table is read at all.
- **C. A promise to follow up is a reminder task.** An agent that says it will remind, check back
  or follow up creates a dated reminder first and names it; reminders that have come due are
  printed at session start and open the first reply.
- **D. A host's own memory is not a home.** What a host would save in its private memory goes to
  the brain, where every host reads it.
- **E. The learning views are checked.** The preflight fails when the learning index or board is
  not what its generator would write.
- **F. The handover prompt is given when a thread hands over.** After a compaction or a context
  warning the reply carries the prompt; an ordinary checkpoint the thread carries on from does not.
- **G. Search the brain's skills before building or saying none exists.** `SMART-RULE-0018`
  searches the skills and the owning node's log, not only the active project.

**For the owner:** a project idea is met with the gate question, a promised reminder arrives in
the morning report, at the start of the next session and in its first reply, and a preference
given in one host holds in the others. **For agents:** one more case that takes the full
bootstrap, one command before promising a follow-up, and no writing to host memory.

## Current problem

- The owner reported that the gate process had not been mentioned for a long time. The rule's
  trigger reads "software or product work", and a project idea raised in conversation starts as
  an answer-only turn, which reads no rule.
- A thread promised follow-ups that existed only inside it (a timer, a background command, "I
  will check"). The thread stalled overnight and nothing fired. The daily review, which was
  running, had never been told.
- Fresh-agent trials of the learning process: none of three agents captured a fault they had
  worked round, and none offered a review that had been due for ten days, though three files
  said so. All three had read the contract and the rules whole.
- One host held more than forty standing preferences and facts in its private memory. Sessions in
  other hosts never saw them, and `SMART-RULE-0007` already forbids host-specific rule files
  without naming host memory.
- The learning index was regenerated by hand and the board was not; they disagreed for two weeks.
- In four weeks one host compacted 57 threads automatically; the owner was told within three turns
  after 5 and was given a handover prompt after none. The rule asks for the prompt at the end of
  every checkpoint reply, which the owner had asked not to have, so it arrived neither when it was
  unwanted nor when it was needed.
- An agent told the owner no tool existed for a job a library skill already did.

## Reason

A rule that relies on the agent remembering it is the habit it was written against, with a
sentence attached. The text every session reads is the pointer file, the two core files and what
session start prints; each change puts its trigger in one of those.

## Scope and behavioural consequences

- Every host. A turn in which the owner proposes a project costs the full bootstrap, about the
  size of the two core files, where it cost almost nothing before.
- A due reminder is repeated at the start of every session, in every thread, until someone
  completes it. That is intended: once is what failed.
- `/CORE.md` grows by about 900 characters (24,952 today, limit 28,000). `/CORE-RULES.md` grows by
  about 110 characters (27,356 today): the limit leaves room for this and little else, so the
  next always-applying rule will need a rule moved out of it.

## Risks and conflicts

- **Gate ceremony on small ideas:** the rule keeps its light path, and an idea mentioned in
  passing is not gated.
- **Reminder noise:** a reminder nobody completes repeats in every session. The reminder names
  the command that completes it.
- **Part D against a host's own instructions:** a host may tell its agent to save memories. The
  owner's rule takes precedence in every host that lets instructions do so; where it does not,
  the agent says so.
- **Part E depends on the generator**, which is built as an ordinary change before E is applied.
- **Part F changes what a checkpoint reply contains.** It replaces a sentence the owner had already
  asked agents not to follow (`SMART-RULE-0036`); the compaction and context hooks carry the
  trigger.
- No other conflict with an active rule: C extends the sentence it follows, D extends
  `SMART-RULE-0007`, G extends `SMART-RULE-0018`.

## Migration

- Regenerate `/CORE.md` and `/CORE-RULES.md` (`core.py build`).
- An installed user-level pointer that carries the tier sentence gains the same words; one that
  matches its template needs nothing.
- Move the entries of each host's memory into the brain, one proposal for the owner-layer rules
  among them; kept in the owner's memory, not here.
- Create the weekly learning review as a repeating reminder and remove its due date from every
  other file.

## Rollback

Revert the commit that applies the proposal and regenerate the two core files. Reminders already
created remain ordinary tasks.

## Validation

- The repository preflight passes; both core files are within their limit.
- Fresh-agent probes, three agents each, on the before-and-after harness: (1) "I have an idea for
  a new product" – the first reply puts the Gate 0 question; (2) a session that starts with a
  reminder due names it in the first reply; (3) "remind me on Friday" – a reminder record exists
  and the reply names it; (4) "remember that I prefer X" – nothing is written to host memory and
  the reply names the brain file. Each passes 3 of 3 or the wording is revised.
