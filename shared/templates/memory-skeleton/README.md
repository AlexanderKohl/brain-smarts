# Memory

Read `/CONTRACT.md` first. This is the owner's memory: the second layer of the brain
(CONTRACT §3.4), a separate private repository checked out at `<brain_root>/memory/` and
addressed as `/memory/...` in every repository-root path.

## Navigation

Entries are in reading order.

- `/memory/OWNER.md`: the owner profile
- `/memory/RULES.md`: owner-layer rules, inherited by every node in the brain
- `/memory/ONBOARDING_OWNER.md`: owner-specific operating notes
- `/memory/STATE.md`: current state of the whole brain
- `/memory/LOG.md`: brain-wide significant events
- `/memory/KNOWLEDGE.md`: durable brain-wide knowledge
- `/memory/repository-manifest.json`: generated by the preflight validator for this repository

#### Folders

##### `governance/`

Contains proposals for changes to owner-layer governance (`/memory/RULES.md` and node `RULES.md` files in memory) under `governance/proposals/`. Proposals are not active until accepted and implemented (CONTRACT §13.2).

##### `projects/`

Contains canonical project nodes for work kept in memory, and one pointer node for each project that lives in its own repository (CONTRACT §7.1 and §16).

##### `raw/`

Contains canonical immutable source files, organised as `raw/YYYY/MM/<source-id>/`. Preserve every file byte for byte (CONTRACT §11.1).

##### `skills/`

Contains owner configuration, data and notes for shared skills, one folder per skill at `skills/<skill>/`, mirroring the skill's inner layout. The skills themselves stay canonical in `/shared/skills/`.

##### `sources/`

Contains canonical Markdown representations of raw source files. Each record keeps its provenance and a link to its immutable raw file.

##### `systems/`

Contains owner-side operating history for mechanics system nodes, at the same path as the node in the mechanics repository (for example `systems/raw-file-management/`).

##### `tasks/`

Contains the canonical cross-project task system. Tasks exist once here and reference every relevant project or dependency.
